# גישה בתשלום — הרשמה עצמית + אימות ביקוש (לפני חיבור סליקה)

> המודל: כל חייל **נרשם בעצמו** (אימייל+סיסמה) — אפס עבודה שלך. התוכן נעול, ורק מי
> שנמצא ברשימת "שילמו" (members) רואה אותו. בשלב הזה **עוד אין סליקה** — אנשים
> נרשמים ונתקלים בקיר רכישה, ואת **מודדת כמה נרשמו** (ב-Supabase → Authentication →
> Users). כשיהיה ביקוש — מחברים ספק סליקה, ומאותו רגע הגישה נפתחת אוטומטית.

## איך זה עובד לחייל
פותח קישור → «הרשמה» (אימייל+סיסמה) → נכנס → רואה «החשבון עדיין לא הופעל / רכישה» →
(בעתיד: משלם → נפתח אוטומטית). בינתיים: את רואה אותו ברשימת הנרשמים.

## המצב כרגע (בנוי באפליקציה)
- ✅ הרשמה עצמית + התחברות (אימייל+סיסמה) — בלי קודים, בלי תלות בשירות מייל.
- ✅ קיר רכישה למי שנרשם ולא שילם.
- ✅ קריאות התוכן נושאות את טוקן המשתמש (מוכן ל-RLS).
- ✅ טבלת `members` (רשימת "שילמו") + אתה ברשימה — כבר נוצרו.
- ✅ הנעילה **כבויה** (`window.LOGIN_GATE`) עד שנסיים.
- ⏳ נשאר: 3 הגדרות ב-Supabase, ואז מדליקים.

---

## צעד A — כיבוי אישור מייל (כדי שהרשמה תהיה מיידית, בלי מייל)
Authentication → הגדרות → **Confirm email** → **לכבות** (OFF) → Save.
כך חייל שנרשם נכנס מיד, בלי לחכות למייל אישור (וזה גם מונע את בעיית ה-429).
> «Allow new users to sign up» — להשאיר **ON**.

## צעד B — טבלת "שילמו" (כבר קיים)
נוצר קודם. תזכורת להפעלת חייל ששילם (בהמשך יעשה זאת ה-webhook אוטומטית):
```sql
insert into public.members (email, note) values ('soldier@example.com', 'שילם 20/9');
```
לבטל גישה = למחוק את השורה.

## צעד C — לנעול את טבלת התוכן (RLS) — הלב של ההגנה
```sql
alter table public.phrases enable row level security;
create policy "paid members read" on public.phrases
  for select using (
    lower(auth.jwt() ->> 'email') in (select lower(email) from public.members)
  );
```
> ⚠️ ודאי שאת ב-members לפני שמריצים (כדי שלא תיחסמי).
> אם יש עוד טבלאות תוכן/מדיה — נחיל עליהן את אותו היגיון.

## צעד D — להדליק את הנעילה
- **בדיקה במכשירך (בלי console):** פתחי את הכתובת עם `?login=1` בסוף → יופיע מסך ההרשמה.
  לכיבוי: אותה כתובת עם `?login=0`.
- **להשקה לכולם:** אני משנה את ברירת המחדל בקוד ל-ON ודוחפת גרסה.

---

## שלב אימות הביקוש (עכשיו)
1. משתפים קישור בוואטסאפ.
2. חיילים נרשמים (אימייל+סיסמה) → רואים קיר רכישה.
3. את סופרת נרשמים ב-Supabase → Authentication → **Users**.
4. יש מספיק ביקוש? מחברים ספק סליקה.

## חיבור סליקה (כשיהיה ביקוש)
בוחרים ספק (Grow/PayPlus/Tranzila/Cardcom או Stripe) → דף תשלום + webhook
שמוסיף אוטומטית ל-members אחרי תשלום. שאר המנגנון (הרשמה, נעילה, מסכים) כבר בנוי.
