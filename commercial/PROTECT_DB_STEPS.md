# נעילת המאגר לפני הפיילוט: צעד אחר צעד

> ✅ **בוצע ב־12.10.2026.** הבדיקה מול המאגר האמיתי: המאגר מוגן, 0 משפטים בלי התחברות, כתיבה חסומה (401), המנהלת רואה הכול. גם הבדיקה כמשתתף (הרשמה ← "החשבון עדיין לא הופעל" ← אישור ב-members ← הערכה נפתחת) והבדיקה במצב טיסה עברו בטלפון.

**הקבצים:**
- `04_protect_db.sql`: הנעילה.
- `05_unprotect_db.sql`: ביטול חירום.

**מה נבדק לפני שהקוד הגיע אלייך:** הסקריפט רץ על עותק של מסד נתונים בנוי כמו Supabase, בשני מצבים: כשההגנה כבויה לגמרי, וכשיש מדיניות פתוחה. התוצאות:

| מי | לפני | אחרי |
|---|---|---|
| בלי התחברות: קריאה | כל המשפטים | 0 |
| בלי התחברות: הוספה, שינוי, מחיקה | מצליח (אפשר למחוק את הכול!) | חסום |
| נרשם שלא אושר | כל המשפטים | 0 |
| חבר מאושר (members) | כל המשפטים | כל המשפטים, בלי עריכה |
| המנהלת | הכול | הכול, כולל עריכה והוספת חברים |

- **עצירה בטוחה:** אם המייל של המנהלת לא קיים, הסקריפט עוצר ולא משנה כלום.
- **בדיקה עצמית:** בסוף הסקריפט יש בדיקה. אם היא נכשלת, הכול מתבטל והמאגר נשאר בדיוק כמו שהיה.
- **ביטול חירום:** נבדק שהוא פותח שוב את הקריאה, ושהרצה חוזרת של הנעילה סוגרת אותה שוב.

הערכה עצמה כבר מוכנה: ברגע שהמאגר יינעל, היא תציג מסך כניסה. בהתחלה תופיע אותה מסך הפתיחה, ואחריו מסך הכניסה.

---

## 0. "לפני": תמונת מצב (דקה)
בערכה ← ניהול ← **🔐 בדיקת הגנת המאגר**.
סביר שתראי ⚠️ "המאגר חשוף". זו הפרצה שאנחנו סוגרים.

## 1. הגדרת הרשמה ב-Supabase (דקה)
Supabase ← **Authentication** ← **Sign In / Providers** ← **Email**:
- **Confirm email: לכבות (OFF).** כך משתתף שנרשם נכנס מיד, בלי לחכות למייל אישור.
- **Allow new users to sign up: להשאיר דלוק (ON).**
- לשמור (**Save**).

## 2. לוודא את המייל של המנהלת (דקה)
Supabase ← **Authentication** ← **Users**. מוצאים את המייל שאיתו את נכנסת לניהול בערכה.
- **אם זה hagaiedit@gmail.com:** לא צריך לשנות כלום.
- **אם זה מייל אחר:** בקובץ `04_protect_db.sql` מחליפים את המייל **בשורה אחת בלבד**, השורה שמתחילה ב־`select set_config('app.admin_email'`.

## 3. הנעילה (2 דקות)
Supabase ← **SQL Editor** ← **New query** ← מדביקים את כל התוכן של `04_protect_db.sql` ← **Run**.
- **הצליח:** מופיע **Success**, בלי שגיאה אדומה.
- **נכשל:** מופיעה שגיאה אדומה שמתחילה ב"עצירה" או "בדיקה נכשלה". שום דבר לא השתנה. צלמי מסך ושלחי לי.

## 4. "אחרי": בדיקה מול המאגר האמיתי (דקה)
בערכה ← ניהול ← **🔐 בדיקת הגנת המאגר**. צריך לראות:
- ✅ המאגר מוגן
- ✅ קריאת משפטים בלי התחברות: 0
- ✅ קריאת רשימת החברים: 0
- ✅ הוספה/שינוי תוכן: חסום
- ✅ המנהלת רואה את התוכן: כן

## 5. בדיקה כמו משתתף אמיתי (3 דקות)
1. בטלפון, פותחים **חלון גלישה פרטית** ונכנסים לקישור של הערכה.
2. מופיע מסך הפתיחה, ואחרי "כניסה לערכה" מופיע **מסך כניסה**, בלי תוכן.
3. נרשמים עם מייל לבדיקה. מופיע "החשבון עדיין לא הופעל" עם כפתור "📲 שליחת המייל לאדית בוואטסאפ".
4. ב-Supabase ← **Table Editor** ← **members** ← **Insert row** ← כותבים את המייל ← **Save**.
5. חוזרים לטלפון ← "✓ אושרתי — בדוק שוב" ← הערכה נפתחת.

## 5א. בדיקת עבודה בלי קליטה (2 דקות)
עם אותו משתמש מאושר מסעיף 5:
1. פותחים כמה משפטים ומשמיעים אותם, כשיש קליטה.
2. מעבירים את הטלפון למצב טיסה, סוגרים את הערכה ופותחים אותה שוב.
3. התוכן אמור להופיע (בפינה כתוב "אופליין · תוכן שמור"), וההקלטות שכבר הושמעו אמורות לעבוד.

## 6. כל משתתף בפיילוט
אותו מסלול כמו בסעיף 5: המשתתף נרשם ושולח לך את המייל בוואטסאפ, את מוסיפה שורה ב-**members**, והוא לוחץ "בדוק שוב".
כדי לבטל גישה, מוחקים את השורה שלו.

## 🆘 אם משתמשים מאושרים לא רואים תוכן
SQL Editor ← מדביקים את `05_unprotect_db.sql` ← **Run**.
הקריאה נפתחת שוב כמו קודם, והעריכה נשארת רק אצלך. אחר כך תכתבי לי מה קרה.

## איפה נמצאות ההקלטות
לא ב-Supabase Storage. הן ב-**Cloudinary**, והמאגר שומר רק את הקישור לכל הקלטה. הנעילה מסתירה את הקישורים, אבל הקבצים עצמם לא נעולים (ראו למטה).

## מה הנעילה הזו לא מכסה (כדי שיהיה ברור)
- **קובצי ההקלטות (Cloudinary):** הם קישורים ציבוריים. מעכשיו זר לא יכול לקבל את הקישורים, אבל מי שכבר שמר קישור יוכל להשמיע אותו. הגנה מלאה על האודיו היא שלב נפרד, לפני המכירה הרחבה.
- **טקסט שבנוי בתוך הערכה עצמה:** בערך 560 מילים במילון, כ־260 שורות תרחישים, ותבניות של מסכי השטח. משתמש טכני יכול לקרוא אותם מקוד הדף גם כשהערכה נעולה. ההקלטות, התשובות של האזרח ורוב המשפטים נמצאים במאגר, והם מוגנים.
- **עותקים שמורים במכשירים:** מכשיר שפתח את הערכה בעבר שומר עותק של התוכן. כשהוא מתחבר שוב בלי אישור, העותק נמחק אוטומטית.
