# הפעלת שכבת המסחר — מדריך צעד-אחר-צעד (בלי מפתח)

מסמך זה נכתב כדי שתוכלי **להפעיל בעצמך** את מודול המנויים והתשלום — בלי לשכור מפתח.
כל הקוד כבר בנוי (התחברות, זכאות, סכימת מנויים, webhook של Stripe, הגנת מדיה).
מה שנשאר הוא **הפעלה**: פתיחת חשבונות, הדבקת קוד מוכן, וקבלת החלטות. אין כאן כתיבת קוד.

> ⚠️ **חוק הזהב:** אל תריצי את `03_rls_content.sql` עד שלב 6. הרצה מוקדמת שלו
> "נועלת" את התוכן לפני שיש התחברות ותשלום — וכל התוכן ייעלם מהאפליקציה החיה.
> כל שאר השלבים בטוחים ולא שוברים כלום.

## החלטות שצריך לקבל לפני שמתחילים
1. **מה חינם ומה בתשלום** (אסטרטגיית טעימה) — למשל: כל היסודות + נושא מבצעי אחד חינם; שאר המבצעי + התרחישים = premium. (נערך בשלב 2.)
2. **מחיר ומודל** — לפי ההמלצה שלי: **עונתי/רבעוני חד-פעמי** (למשל 99 ₪) פשוט יותר ממנוי חודשי.
3. **שיטת התחברות** — טלפון+OTP (מומלץ לקהל) או אימייל.

אם עדיין לא החלטת — אפשר לרוץ עד סוף שלב 3 בבטחה, ולהחליט לפני שלב 4.

## שלב 0 — מה צריך ביד
- גישת אדמין ל-**Supabase** של הפרויקט (כבר קיים).
- חשבון **Stripe** (חינם לפתיחה) — [stripe.com](https://stripe.com).
- התקנת **Supabase CLI** (פעם אחת) — או שאבצע איתך את הפקודות. מדריך: `npm i -g supabase`.

---

## שלב 1 — טבלאות המנויים (בטוח, 2 דקות)
1. Supabase → **SQL Editor** → New query.
2. פתחי את `commercial/01_schema.sql`, העתיקי הכל, הדביקי, לחצי **Run**.
3. זה יוצר `profiles`, `subscriptions`, והפונקציה `is_subscribed()`. **לא נוגע בתוכן — כלום לא נשבר.**

## שלב 2 — תיוג חינם/בתשלום (בטוח, החלטה שלך)
1. פתחי את `commercial/02_content_tier.sql`.
2. בתוך הקובץ יש שורות `UPDATE ... SET tier='premium' WHERE ...` — **ערכי אותן** לפי ההחלטה שלך (מה premium).
   - ברירת מחדל: הכול `free`. כל מה שלא תסמני כ-premium נשאר חינם.
3. הריצי את הקובץ ב-SQL Editor. עדיין **שום דבר לא ננעל** — רק תיוג. אפשר לשנות שוב מתי שרוצים.

## שלב 3 — הפעלת התחברות (Supabase Auth)
1. Supabase → **Authentication** → **Providers**.
2. לטלפון+OTP: הפעילי **Phone**, וחברי ספק SMS (Twilio / MessageBird — דורש חשבון אצלם).
   - חלופה קלה יותר להתחלה: **Email OTP** (בלי ספק SMS). לשנות ב-Providers.
3. בשלב הזה משתמש יכול להתחבר — **אבל התוכן עדיין פתוח לכולם. כלום לא נשבר.**

## שלב 4 — סליקה (Stripe)
1. Stripe Dashboard → **Products** → צרי מוצר ("ערבית מצילה חיים — עונה") + מחיר (חד-פעמי או מנוי).
2. פרסי את פונקציית ה-webhook (Supabase CLI):
   ```
   supabase functions deploy stripe-webhook --no-verify-jwt
   supabase secrets set STRIPE_SECRET_KEY=sk_... STRIPE_WEBHOOK_SECRET=whsec_... \
     SUPABASE_URL=https://<proj>.supabase.co SUPABASE_SERVICE_ROLE_KEY=<service-role-key>
   ```
   *(את המפתחות לוקחים מ-Stripe → Developers → API keys, ומ-Supabase → Settings → API. אני יכול ללוות אותך בכל שורה.)*
3. Stripe → **Developers → Webhooks** → הוסיפי endpoint ל-URL של הפונקציה, עם האירועים:
   `checkout.session.completed`, `customer.subscription.updated`, `customer.subscription.deleted`, `invoice.payment_failed`.
4. **בדיקה:** בצעי תשלום מבחן (Stripe test mode) → ודאי שהשורה ב-`subscriptions` הופכת ל-`active`.

## שלב 5 — חיווט הקליינט (קוד — כאן אני נכנס)
זה החלק היחיד שהוא קוד, ואני מבצע אותו כשתגיעי לכאן:
- הפעלת `COMMERCE_LOGIN` כברירת מחדל.
- מסך "שדרג למנוי" + גיטינג: תוכן premium מוצג רק אם `clHasAccess()` מחזיר אמת, אחרת כפתור שדרוג.
- חיבור כפתור התשלום ל-Stripe Checkout שמעביר את `supabase_user_id`.

**עד השלב הזה התוכן עדיין פתוח — בטוח לפרוס.**

## שלב 6 — נעילת החומה (⚠️ רגע ה"סגירה")
**רק אחרי ששלבים 1–5 עובדים ונבדקו:**
1. Supabase → SQL Editor → הריצי את `commercial/03_rls_content.sql`.
2. בקובץ יש placeholder ל-UUID של האדמין — החליפי אותו ב-UUID שלך (Supabase → Authentication → Users).
3. מרגע זה: אנונימי רואה `free` בלבד; מנוי רואה הכול. **המוצר "נסגר".**

## שלב 7 — הגנת מדיה (אופציונלי, מאוחר יותר)
הקלטות ב-Cloudinary עדיין URL ציבורי. כשתרצי — מפעילים signed delivery + פורסים `media-sign` (ראי `commercial/MEDIA.md`). אפשר להשאיר לשלב שני.
